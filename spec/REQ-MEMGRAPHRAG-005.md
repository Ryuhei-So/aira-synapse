## 1. 背景と動機

v0.3.5 で英語 HotpotQA 500 問に対して **90.0%** の精度を達成した。しかし、AI for Science の実用化には**日本語論文への対応**が不可欠であり、日本語でのマルチホップ推論能力を定量的に評価するベンチマークが存在しない。

### 1.1 問題

- 公式の日本語 HotpotQA データセットは存在しない（2026年6月時点）
- JSQuAD (JGLUE) は単一ホップのみでマルチホップ推論を測定できない
- 日本語パイプラインの精度を定量的に評価する手段がない

### 1.2 アプローチ: 翻訳方式

既存の英語 HotpotQA 500 問を日本語に翻訳し、対応する日本語 Wikipedia 記事をコーパスとして使用する。

```
英語 HotpotQA 500問
  ↓ LLM 翻訳（質問 + 正解）
日本語 HotpotQA 500問
  ↓
日本語 Wikipedia 記事を取得（supporting documents）
  ↓ MemGraphRAG インデキシング
日本語ナレッジグラフ
  ↓ ベンチマーク実行
日本語精度スコア
```

### 1.3 リスク

| リスク | 影響 | 対策 |
|-------|------|------|
| 日本語 Wikipedia に対応記事がない | コーパスギャップで精度低下 | 事前にカバレッジ調査し、対応記事がない問題を除外 |
| 翻訳品質のばらつき | 質問の意味が変わる | LLM 翻訳 + サンプル人手検証 |
| 固有名詞の日英不一致 | エンティティ認識の失敗 | 日英固有名詞マッピングテーブルを作成 |
| 文化的コンテキストの欠落 | 日本語 Wiki に情報がない | カバレッジ率を指標として追跡 |

## 2. 要件

### REQ-005-001: 日本語 HotpotQA データセット生成

**種別**: EVENT-DRIVEN
**優先度**: P0

**要件**:
WHEN ユーザーが日本語ベンチマークデータセットの生成を要求する, THE システム SHALL 英語 HotpotQA の質問・正解ペアを日本語に翻訳し、JSON 形式で出力する。

**受入基準**:
- [ ] 英語 HotpotQA 500 問の質問文が日本語に翻訳される
- [ ] 正解（answer）が日本語に翻訳される
- [ ] 翻訳元の英語テキストが保持される（`original_question`, `original_answer`）
- [ ] 出力形式が既存の `hotpotqa_500.json` と互換性のある構造を持つ
- [ ] bridge / comparison の問題タイプが保持される

**トレーサビリティ**: DES-MEMGRAPHRAG-005（未作成）
**パッケージ**: `@nahisaho/memgraphrag`

---

### REQ-005-002: 日本語 Wikipedia コーパス取得

**種別**: EVENT-DRIVEN
**優先度**: P0

**要件**:
WHEN 日本語 HotpotQA データセットが生成された, THE システム SHALL 各問題の supporting documents に対応する日本語 Wikipedia 記事を取得し、Markdown 形式で保存する。

**受入基準**:
- [ ] 各問題の supporting documents（2記事/問）に対応する日本語 Wikipedia 記事を取得する
- [ ] 日本語 Wikipedia に対応記事がない場合、その問題にフラグ（`ja_coverage: false`）を付与する
- [ ] 取得した記事が Markdown 形式で `data/corpus/hotpotqa-ja/` に保存される
- [ ] コーパスカバレッジ率（対応記事が存在する問題の割合）を算出・レポートする

**トレーサビリティ**: DES-MEMGRAPHRAG-005（未作成）
**パッケージ**: `@nahisaho/memgraphrag`

---

### REQ-005-003: 日本語コーパスのインデキシング

**種別**: EVENT-DRIVEN
**優先度**: P0

**要件**:
WHEN 日本語 Wikipedia コーパスが取得された, THE システム SHALL 既存のインデキシングパイプラインで日本語テキストを処理し、ナレッジグラフを構築する。

**受入基準**:
- [ ] 日本語テキストのチャンキングが正常に動作する
- [ ] LLM によるファクト抽出が日本語テキストに対して動作する
- [ ] エンティティ正規化が日本語固有名詞に対応する
- [ ] 構築されたグラフのノード数・エッジ数がレポートされる
- [ ] インデキシング完了後、PPR およびベクトル検索が動作する

**トレーサビリティ**: DES-MEMGRAPHRAG-005（未作成）
**パッケージ**: `@nahisaho/memgraphrag`

---

### REQ-005-004: 日本語ベンチマーク実行

**種別**: EVENT-DRIVEN
**優先度**: P0

**要件**:
WHEN 日本語ナレッジグラフが構築された, THE システム SHALL 日本語 HotpotQA データセットに対してベンチマークを実行し、精度スコアを算出する。

**受入基準**:
- [ ] 日本語の質問に対して日本語で回答を生成する
- [ ] 既存の評価ロジック（fuzzyMatch, synonymMatch 等）が日本語に対応する
- [ ] bridge / comparison 別の精度内訳を算出する
- [ ] 英語版ベンチマーク（90.0%）との比較レポートを生成する
- [ ] `ja_coverage: false` の問題は精度計算から除外する

**トレーサビリティ**: DES-MEMGRAPHRAG-005（未作成）
**パッケージ**: `@nahisaho/memgraphrag`

### REQ-005-005: ベンチマークスクリプト

**種別**: EVENT-DRIVEN
**優先度**: P1

**要件**:
WHEN ユーザーが日本語ベンチマークの実行を要求する, THE システム SHALL 単一コマンドでデータセット生成・コーパス取得・インデキシング・ベンチマーク実行の全パイプラインを実行できるスクリプトを提供する。

**受入基準**:
- [ ] `node scripts/benchmark-hotpotqa-ja.mjs` で全パイプラインが実行できる
- [ ] 各ステップ（翻訳、コーパス取得、インデキシング、ベンチマーク）を個別に実行するサブコマンドがある
- [ ] 中間成果物がキャッシュされ、再実行時にスキップできる
- [ ] 実行結果が `data/benchmark/hotpotqa-ja/` に保存される

**トレーサビリティ**: DES-MEMGRAPHRAG-005（未作成）
**パッケージ**: `@nahisaho/memgraphrag`

### REQ-005-006: 日本語評価ロジック

**種別**: COMPLEX
**優先度**: P0

**要件**:
IF 回答が日本語である場合, THEN THE システム SHALL 日本語特有の表記揺れ（漢字/ひらがな/カタカナ、全角/半角、送り仮名の違い等）を考慮した評価ロジックで正解判定する。

**受入基準**:
- [ ] 全角/半角の正規化（「ＡＩ」→「AI」）
- [ ] カタカナ/ひらがな変換の考慮（「コンピュータ」=「コンピューター」）
- [ ] 長音記号の正規化（「サーバー」=「サーバ」）
- [ ] 漢字の異体字対応（「斉」=「齊」等、基本的なもの）
- [ ] 助詞・接尾辞の除去（「東京都」→「東京」でもマッチ）
- [ ] 既存の fuzzyMatch との統合（Levenshtein 距離ベース）

**トレーサビリティ**: DES-MEMGRAPHRAG-005（未作成）
**パッケージ**: `@nahisaho/memgraphrag`

## 3. 非機能要件

### REQ-005-NF-001: 翻訳コスト

**種別**: UNWANTED
**優先度**: P1

**要件**:
THE システム SHALL NOT 翻訳に $50 以上の LLM API コストを発生させない。

**受入基準**:
- [ ] 500問の翻訳コストが $50 以下
- [ ] 翻訳結果がキャッシュされ、再実行時に API 呼び出しが発生しない

---

### REQ-005-NF-002: ベンチマーク実行時間

**種別**: STATE-DRIVEN
**優先度**: P2

**要件**:
WHILE ベンチマークが実行中, THE システム SHALL 500問のクエリ応答を120分以内に完了する。

**受入基準**:
- [ ] 500問のベンチマーク実行が120分以内
- [ ] 並行実行数（concurrency）の設定が可能
