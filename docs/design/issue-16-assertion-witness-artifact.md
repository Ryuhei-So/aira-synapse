# Issue 16 assertion-witness artifact

## Authority and data flow

Synapse remains the sole authority for bounded-retrieval semantics. The
canonical operation declarations, refinement programs, evaluator, and bounded
exchange fixture jointly generate a compact negative witness for every
independently executable request/exchange semantic clause. Canonical programs
must therefore expose independent clauses as separate top-level assertions;
an aggregate assertion may not hide independently removable `all`/`any`
children behind one witness identity. GraphDB may pin and execute those witnesses, but
must not restate a rule catalog or invent replacement mutations.

The existing three-file artifact remains closed. Witnesses live in the fixture
artifact, and the manifest authorizes the resulting fixture bytes and exact
per-operation/partition witness counts. A witness identity is derived from the
canonical operation, partition, and zero-based assertion index; ordering is
canonical operation order, then request before exchange, then assertion index.

Each witness contains only a closed replacement patch over the corresponding
valid fixture exchange: root (`request` or `result`), an RFC 6901 pointer to an
existing value, and its replacement JSON value. A witness never contains code,
callbacks, absolute paths, or a second copy of the refinement assertion.

## Schema, invariants, and state

- Fixture version advances before its shape changes. Unknown fixture or
  witness versions fail closed.
- Every canonical assertion has exactly one witness identity; missing,
  duplicate, extra, reordered, unknown-operation, unknown-partition, and
  out-of-range identities fail closed.
- Applying a witness is pure and copy-on-write. The target pointer must exist,
  must not cross the selected request/result root, and the patch has exactly
  `root`, `path`, and `value`.
- The unmodified fixture passes schema, request assertions, and exchange
  assertions. For each witness, the producer evaluator proves the addressed
  assertion false on the patched exchange. Request witnesses are also rejected
  by request validation; exchange witnesses are rejected by full exchange
  validation. A mutation that fails only schema validation is not an assertion
  witness.
- Manifest coverage counts are derived from the canonical programs, not from a
  handwritten expected-number table. Fixture witness identities and counts
  must match that derivation exactly.
- The producer owns a distinct 96 KiB publication budget, selected after the
  pinned-domain projection measured 79,681 bytes (about 23% growth headroom). This is
  intentionally stricter than, and does not redefine, GraphDB's independent
  allocation cap. Producer baselines use the smallest non-vacuous arrays that
  can witness length, uniqueness, ordering, and identity rules; publication
  fails before writing if generated bytes exceed the producer budget.
- Compact Passage, Fact, and Schema values are projections of the pinned
  bounded-domain fixture. The generator must not claim that dependency while
  replacing it with unrelated hand-authored domain objects.
- Native consumes the pinned artifact bytes and uses the same identities and
  patches in tests. It may implement the closed patch transport and assertion
  evaluation, but not a parallel semantic mutation catalog.

There is no persistent or concurrent state. Generation sessions, deadlines,
work counters, native algorithms, availability, and publication remain outside
this producer artifact.

## Failure, privacy, compatibility, and rollback

Generation and `--check` fail before publication on any non-canonical patch,
coverage mismatch, non-failing target assertion, stale manifest link, or
unknown version. Publication remains manifest-last and exact-byte checked.
Witnesses use only the synthetic bounded fixture and contain no query text,
production identifiers, paths, credentials, or logs.

This is a versioned artifact change. Downstream pins must update the producer
commit plus contract, fixture, and manifest hashes atomically. Older consumers
reject the new fixture version; no consumer may silently ignore witnesses.
Rollback restores all three prior artifact bytes and their prior pin together.

## Non-goals

- No GraphDB retrieval algorithms or Hub wiring.
- No timeout increase, partial-success result, lighter query, or full snapshot.
- No handwritten native rule/mutation allowlist.
- No production service, data, or cutover change.

## Adversarial acceptance tests

1. Expose each independently removable semantic clause as its own canonical
   assertion, derive the exact identity set from those request/exchange arrays,
   and compare it byte-for-byte with the generated witness identity set.
2. Remove, duplicate, reorder, rename, or add one witness; generation/check and
   consumer validation fail closed.
3. Change operation, partition, index, patch root, pointer, or patch key set;
   reject before evaluation or publication.
4. Make any patch leave its addressed assertion true; producer generation
   fails and the stale artifact cannot pass `--check`.
5. Add one canonical assertion without a witness; coverage fails mechanically.
6. Apply every witness to the valid fixture and prove the addressed assertion
   fails under the canonical evaluator, while the baseline remains valid.
7. Preserve exact dependency pins, deterministic bytes, manifest-last
   publication, and unknown CLI/version rejection.
8. Keep the fixture below the producer-owned 96 KiB publication budget and
   prove length/uniqueness/order witnesses remain non-vacuous on compact
   baselines.
9. Mutate a field used by the pinned bounded-domain fixture projection and
   prove retrieval-fixture bytes change or generation fails closed.
