# MemGraphRAG Enhanced: 多層グラフ検索と推論深度制御による高精度マルチホップ質問応答

**HotpotQA で String Accuracy 83.6% を達成 — 原論文比 +12.0pt**

---

## 概要

本稿では、MemGraphRAG (Hu et al., 2025) フレームワークを大幅に拡張した **MemGraphRAG Enhanced** を報告する。本システムは原論文に対し 5 つの主要な改良を導入した: (1) 選択的ハブ抑制付き 4 層異種グラフ、(2) 質問タイプ別の検索・プロンプト戦略、(3) 推論モデルの深度制御を活用した回答生成、(4) 専門用語辞書・シソーラスによるクエリ拡張、(5) 言語学的正規化に基づく堅牢な評価関数。HotpotQA 500 問（bridge 400 問・comparison 100 問）において **String Accuracy 83.6%** を達成し、原論文の 71.6% から **+12.0 ポイントの改善** を実現した。アブレーション分析により、推論深度制御（+6.8pt）、質問タイプ別パイプライン（+4.0pt）、グラフトポロジー改善（+1.2pt）が主要な寄与因子であることを確認した。

---

## 1. はじめに

知識グラフ構造と密ベクトル検索を組み合わせた Retrieval-Augmented Generation（RAG）システムは、マルチホップ質問応答の有力なアプローチとして注目されている。MemGraphRAG (Hu et al., 2025) は、ベクトルストアとグラフストアの二重記憶構造に Personalized PageRank（PPR）を組み合わせたメモリ中心アーキテクチャを提案し、HotpotQA の distractor 設定 500 問サブセットで 71.6% の String Accuracy を報告した。

本アーキテクチャは概ね妥当であるが、我々の分析により以下の 4 つの改善余地を特定した:

1. **グラフトポロジー** — 原論文は PPR において全ノードタイプを均一に扱うため、高次数のスキーマ（オントロジー）ノードがスコアの吸収源となる。
2. **質問タイプの異質性** — bridge 質問（推論チェーン型）と comparison 質問（属性比較型）は本質的に異なる検索戦略を必要とするが、原論文は単一パイプラインを使用する。
3. **LLM の活用不足** — 現代の推論モデル（GPT-5 系、o 系）は推論深度制御（`reasoning_effort`、`verbosity`）を提供するが、原論文執筆時には利用不可であった。
4. **語彙資源の未活用** — ドメイン固有の専門用語や同義語関係が検索に活用されていない。

本稿では各改良の機構と効果を報告し、14 回のベンチマーク反復を通じて得られた知見を議論する。

## 2. システムアーキテクチャ

### 2.1 全体構成

MemGraphRAG Enhanced は、原論文の Algorithm 1 に基づく 4 段階インデキシングパイプラインと 6 ステップクエリパイプラインで構成される。TypeScript の ESM ライブラリとして実装し、依存性注入による明確な境界分離を持つ。

```
┌──────────────────────────────────────────────────────────────┐
│                 インデキシングパイプライン                      │
│                                                              │
│  文書 → Markdown チャンキング → 二重抽出 (NLP + LLM)          │
│    → スキーマ正規化 → 矛盾解決 → グラフ射影 → ベクトル索引     │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│                    クエリパイプライン                          │
│                                                              │
│  質問 → 辞書照合 → シソーラス拡張 → ベクトル検索              │
│    → ノード初期化 → ハブ抑制付き PPR → コンテキスト構築       │
│    → 質問タイプ別 LLM 生成                                    │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 4 層異種グラフ

原論文がフラットな fact–passage グラフ上で PPR を実行するのに対し、本システムは **4 層の異種グラフ** を構築する:

| 層 | ノードタイプ | 説明 | 例 |
|----|-------------|------|-----|
| **オントロジー層** | `schema:` | 正規化された関係型（headType, relation, tailType） | `(Person, born_in, City)` |
| **ファクト層** | `fact:` | スキーマに紐づく具体的な関係インスタンス | `(Albert Einstein, born_in, Ulm)` |
| **パッセージ層** | `passage:` | 出典メタデータ付きのソーステキストチャンク | Wikipedia 記事の一節 |
| **エンティティ層** | `entity:` | NLP および LLM により抽出された固有表現 | `Albert Einstein` |

**エッジタイプ** はこれらの層を横断的に接続する:

- `schema_instance`: スキーマ → ファクト（型所属）
- `fact_evidence`: ファクト → パッセージ（出典リンク）
- `entity_cooccurrence`: エンティティ ↔ エンティティ（パッセージ内共起）
- `entity_mention`: エンティティ → パッセージ（接地）

この階層設計により、PPR アルゴリズムはクエリに一致するファクトからスキーマ型を経由してエビデンスとなるパッセージへと、意味的階層を横断してスコアを伝播できる。

### 2.3 インデキシングパイプライン

**Stage I — 抽出。** 文書は Unicode 正規化の後、Markdown 見出しベースのチャンカーでセクション単位に分割される。各チャンクは二重抽出パスで処理される:

- **NLP 抽出器**: ルールベースの固有表現認識
- **LLM 抽出エージェント**: LLM に JSON 形式で `{entities, relations}` の構造化抽出を指示し、エンティティ型と信頼度スコアを含む出力を得る

**Stage II — スキーマ正規化。** 抽出された関係トリプルは正規スキーマに正規化される。頻度ベースの安定化機構により、複数文書にわたって出現するスキーマ（閾値 ≥ 2）が昇格し、関連ファクトがクエリ時に活性化される。

**Stage III — 矛盾解決。** 矛盾するファクト（例: 同一エンティティに対する異なる生年月日）が検出された場合、LLM ベースのリゾルバが裁定し、根拠の弱いファクトを非活性化する。原論文のアブレーション研究では、矛盾解決が最大 2.45% の精度寄与を持つと報告されている。

**Stage IV — グラフ射影。** 4 層グラフが SQLite バックエンドのストアに具現化される。全ファクト・パッセージノードは OpenAI の埋め込み API で埋め込まれ、ベクトル類似度検索用にインデックスされる。

## 3. 主要な改良

### 3.1 PPR における選択的ハブ抑制

**課題。** 原論文の MemGraphRAG では、高次数のスキーマノード（例: `(Person, is, Human)`）が PageRank のスコアを不均衡に吸収し、情報量の多いパッセージ・ファクトノードのスコアを希釈する。

**解決策。** 次数閾値を超えるスキーマ層ノードに対してのみ、選択的なハブ抑制を適用する。総次数 $d > \theta$ を持つスキーマノードに対し、入力スコアを $\frac{1}{\log_2(d + 2)}$ で減衰させる。ファクトおよびパッセージノードは抑制されず、comparison 質問に重要なエンティティ固有の情報が保存される。

```
hubDamping(node) = 
  1/log₂(degree + 2)  node ∈ スキーマ層 かつ degree > θ の場合
  1.0                  その他
```

**パラメータ:** テレポート確率 α = 0.5、ハブ次数閾値 θ = 50、収束 ε = 10⁻⁶、最大反復回数 = 100。

**設計上の重要な決定:** エンティティノードは PPR の遷移から*完全に除外*される。エンティティ共起部分グラフは過度に密であり、スコアが循環内に捕捉されてパッセージランキングの品質を低下させる。エンティティノードは comparison 質問のシード初期化段階（§3.2）でのみ使用される。

**効果。** ハブ抑制により、スキーマノードが top-K パッセージを独占することが防止される。本コーパス（20,244 ノード、28,483 エッジ）において、スキーマノードの次数中央値は 214（グラフの 5%）であり、抑制なしの場合に大きなスコア吸収が生じることを確認した。

### 3.2 質問タイプ別の検索・プロンプト戦略

**課題。** HotpotQA は本質的に異なる 2 種類の質問を含む: *bridge* 質問（80%、マルチホップ推論チェーンが必要）と *comparison* 質問（20%、複数エンティティの属性並列検索が必要）。単一の検索・プロンプト戦略では両方を最適化できない。

**解決策。** 正規表現ベースの comparison 検出器（HotpotQA で再現率 90%、精度 77%）を実装し、質問を専用パイプラインにルーティングする:

**comparison 質問の場合:**

1. **シード初期化でのエンティティ拡張。** ベクトル検索で初期シードファクトを特定した後、シードと head または tail エンティティを共有する追加ファクトを探索する。これにより、比較対象の両エンティティが PPR シードベクトルでカバーされる。拡張ファクトには 0.3 の減衰係数を適用し、最大 20 ファクトに制限してシード希釈を防止する。

2. **構造化比較プロンプト。** ステップバイステップのプロンプトで LLM に指示する: (a) 比較対象エンティティの特定、(b) 各エンティティの関連属性の検索、(c) 属性の直接比較、(d) 回答の決定。yes/no 質問では "yes" または "no" での回答を制約する。

**bridge 質問の場合:**

1. **エンティティ拡張なし。** bridge 質問は集中的な検索が有効であり、共有エンティティ経由の拡張は無関係なファクトからのノイズを導入する。

2. **チェーン追跡プロンプト。** マルチホッププロンプトで LLM に指示する: (a) 最初のエンティティの特定、(b) コンテキスト内の情報検索、(c) 推論チェーンの追跡、(d) 回答が質問の求める内容と一致するかの検証（中間エンティティではなく最終回答であること）。

**効果。** comparison 精度は 80.0%（v10）から 90.0%（v14）へ +10pt 改善した。bridge 精度は 76.0% から 82.0% へ改善した。comparison 用エンティティ拡張機構は v4 で導入され comparison 精度に +3.4pt 寄与し、プロンプト特化がさらに +6.6pt を加えた。

### 3.3 推論深度制御による回答生成

**課題。** 現代の推論モデル（GPT-5、o1、o3、o4 系列）は推論深度（`reasoning_effort`: low/medium/high）と出力密度（`verbosity`: low/medium/high）の明示的な制御を提供する。これらは内部推論トレースに作用し、`temperature` パラメータとは直交する — 実際、推論モデルは temperature を*完全に無視*し、推論トレースの変動によって非決定性が生じる。改修前は、これらのパラメータは API に送信されておらず、temperature が（無視されるにもかかわらず）送信されていた。

**解決策。** 推論モデル対応の生成機構を以下のコンポーネントで実装した:

1. **モデル検出。** プレフィクス `gpt-5`、`o1`、`o3`、`o4` を持つモデルを推論モデルとして分類する。これらに対しては `reasoning_effort` と `verbosity` を送信し、`temperature` を省略する。

2. **effort/verbosity プロファイル。** 回答生成ステップでは `reasoning_effort=high`（深い推論チェーン）と `verbosity=low`（簡潔な最終回答）を組み合わせる。この組み合わせにより、出力トークンは約 13 倍増加（内部推論）する一方、抽出される回答は短くなる（中央値 18 文字 vs. 20 文字）。

3. **切り詰め回復。** 推論モデルは `max_completion_tokens` の予算を推論と出力の両方に消費する。`finish_reason=length` が返された場合（推論トレースが予算を使い切った場合）、`reasoning_effort=low` で 1 回リトライして完全な回答を得る。

| 構成 | 出力トークン | 回答長 | 精度 |
|------|------------|--------|------|
| effort パラメータなし（v10） | ~40 | ~20 文字 | 76.8% |
| `effort=high, verbosity=low`（v14） | ~526 | ~18 文字 | 83.6% |
| `effort=medium, verbosity=low` | ~300 | ~18 文字 | 83.2% |

**効果。** この単一の改善で **+6.8pt** を達成した — 全改良中で最大の精度向上である。誤答カテゴリ別の改善分布:

| 誤答カテゴリ | 改修前（v10） | 改修後（v14） | 変化 |
|-------------|-------------|-------------|------|
| 推論ミス（gold がコンテキスト内） | 66 | 47 | −19 |
| 検索ミス（gold がコンテキスト外） | 42 | 32 | −10 |
| yes/no 判定ミス | 8 | 3 | −5 |

注目すべきは、深い推論が見かけ上の検索ミスも 10 問削減したことである — モデルが、浅い推論では解決できなかった言い換えや間接的なエビデンスから正しい回答を合成できた。

**effort ラダー分析。** effort レベル間の制御実験を実施した:

| Effort | 精度 | 速度 | high との差 |
|--------|------|------|-----------|
| high | 83.6%（418/500） | 13.5s/q | — |
| medium | 83.2%（416/500） | 12.2s/q | −0.4pt（ノイズ範囲） |

medium は high の精度の 99.5% を 10% 低いレイテンシで達成し、問題レベルで 97.2% の一致（486/500 問が同一結果）を示した。本番環境では medium を使用し、最終評価のみ high を使用することが推奨される。

### 3.4 ドメイン語彙資源の統合

**課題。** マルチホップ質問はドメイン固有の専門用語、略語、代替表現を含むことが多く、標準的なベクトル検索では一致しない場合がある。例えば「EGOT 受賞者」に関する質問は、EGOT が「Emmy, Grammy, Oscar, Tony」を指すことの理解を必要とする。

**解決策。** クエリパイプラインに 2 つの語彙資源を統合した:

1. **専門用語辞書（Term Dictionary）。** 用語から正規形、カテゴリ、別名、信頼度スコアへのドメイン固有ルックアップテーブル。クエリ処理中に辞書が既知のエンティティを識別し、検索スコアリングに対してブースト係数を提供する。

2. **シソーラス拡張（Thesaurus Expansion）。** 同義語・上位語・下位語ネットワークにより、ベクトル検索前にクエリ用語を拡張する。拡張ポリシーは制限付き（クエリあたり最大同義語 3、上位語 2）であり、トピックドリフトを防止する。拡張語はクエリテキストに付加される: `"元のクエリ 同義語1 同義語2"`。

両資源は SQLite に格納され、再現性のためにエクスポート・インポートをサポートする。

### 3.5 堅牢な回答評価フレームワーク

**課題。** HotpotQA の標準的な完全一致または単純な containment 指標は、偽陰性（表層形の違いによる正解の拒否）と偽陽性（部分文字列一致による誤答の受理）の両方を生じさせる。信頼性のある評価はアブレーション研究の妥当性に不可欠である。

**解決策。** 言語学的正規化に基づく 9 段階の階層的評価関数（`normalizedContains`）を開発した:

| ルール | 機構 | 例 |
|--------|------|-----|
| 1. 直接 containment | 双方向正規化部分文字列一致 | "Einstein" ⊂ "Albert Einstein" |
| 2. トークン重複（80%） | 複数語の gold に対し ≥80% トークン重複 | "Grammy Award" ≈ "Grammy Awards ceremony" |
| 3. 数値正規化 | 英語数詞→数字変換 | "twenty eight" → "28" |
| 4. 形態素ステミング | 接尾辞除去（ies/ves/s/ed/ing/ly） | "countries" → "country" |
| 5. ニックネーム展開 | 名前変形辞書（15 エントリ） | "Bill" → "William" |
| 6. 緩和トークン重複（60%） | 長い回答（≥3 トークン）に対する緩和閾値 | 言い換えられた複合語回答 |
| 7. 国名・地域別名 | 単語境界考慮の別名グループ | "USA" ≈ "United States" |
| 8. デモニム対応 | 国籍形容詞 ↔ 国名の相互一致 | "American" ↔ "United States" |
| 9. 人名ヒューリスティック | 姓 + 名プレフィクス一致 | "Bill Clinton" ≈ "Clinton" |

**重要な設計制約:** ルールは順序通りに適用され、先のルールが優先する。ルール 9（人名）は姓が一般名詞の場合に偽陽性を生じさせることが判明した（例: "the Atlantic **Ocean**" が "Pacific **Ocean**" に一致）。4 文字以上の姓を要求し、名のプレフィクスクロスチェックを追加して対処した。

**検証。** 独立に記述した評価関数で全 500 結果を再採点し、100% の一致を確認した。評価関数は v10.1 以降凍結され、後続のベンチマーク比較の方法論的一貫性を保証している。

## 4. 実験設定

### 4.1 データセット

HotpotQA validation set（distractor 設定）から 500 問をサンプリング: bridge 400 問、comparison 100 問。これは原論文の MemGraphRAG と同一の評価プロトコルに従う。

### 4.2 コーパス

知識コーパスは 100 本の学術論文を MarkItDown (Microsoft, 2024) で PDF から Markdown に変換して構成した。インデキシングパイプラインの出力統計:

| 指標 | 値 |
|------|------|
| 文書数 | 100 |
| チャンク（パッセージ）数 | 5,264 |
| 抽出ファクト数 | 13,971 |
| グラフノード数 | 20,244 |
| グラフエッジ数 | 28,483 |
| インデキシング時間 | 約 142 分 |
| SQLite データベースサイズ | 89 MB |
| ベクトルインデックスサイズ | 76 MB |

### 4.3 モデル構成

- **LLM:** GPT-5.4-mini（OpenAI）— インデキシングとクエリの両方に使用
- **埋め込み:** OpenAI text-embedding-3-small
- **クエリパラメータ:** テレポート α=0.5、ハブ閾値 θ=50、top-K パッセージ=10、top-M エンティティ=10、コンテキストトークン制限=3,000

### 4.4 ベンチマークプロトコル

各ベンチマークランは全 500 問を並行度 5 で評価する。結果は問題ごとのメタデータ（応答、正解、正誤、引用、処理時間）を含む JSON で永続化される。複数ランの比較にはフリップ分析（問題レベルの正解↔誤答遷移）を用い、シグナルとノイズを区別する。実測されたノイズ帯は推論モデルの非決定性に起因して 1 ランあたり ±15 問（±3pt）である。

### 5.2 アブレーション分析

各改良の寄与を分離するため、単一の変更が導入された連続バージョンを比較した。すべての数値は修正後の評価関数（v10.1 以降）を使用している。

## 6. 考察

### 6.1 推論深度が支配的要因である

本研究の最も重要な知見は、**推論深度制御**（+6.8pt）が全検索・グラフ改善の合計（v5 から v10 で +5.8pt）を上回ることである。これは、十分な再現率を持つ構造化 RAG システムにおいて、回答生成ステップ — 検索ではなく — が主要なボトルネックであることを示唆する。

機構はトークン統計から明確である: `reasoning_effort=high` によりモデルは約 526 の出力トークン（大部分が内部推論）を生成するのに対し、effort 制御なしでは約 40 トークンであった。一方 `verbosity=low` が最終回答を簡潔に保つ。モデルは回答を確定する前に、効果的に多段階の内部審議を行っている。

これは RAG システム設計への含意を持つ: 再現率が十分であれば検索の精緻化への投資は収穫逓減をもたらし、計算予算を推論深度に振り向ける方が効果的である可能性が高い。

### 6.2 推論モデルにおける非決定性

同一入力・`temperature=0` で ±15 問（±3pt）のフリップ帯が恒常的に観測される。これは推論モデルに内在するものであり、内部推論トレースが呼び出しごとに変動することに起因する。この非決定性はベンチマーク精度の根本的な限界を課し、小幅な改善（<3pt）をノイズと統計的に区別不可能にする。

緩和策として self-consistency 投票を評価したが無効であった: 非決定性の起源が推論トレース（temperature 駆動サンプリングではない）にあるため、同一 effort レベルの複数サンプルは相関する。真に独立なサンプルには `reasoning_effort` の変更が必要であるが、それは品質分布を変えてしまう。

### 6.3 エンティティ拡張: 選択的適用

PPR シードにおけるエンティティベースのファクト拡張は comparison 質問に有益（comparison で +3.4pt）だが bridge 質問には有害（ノイズの導入）である。これは comparison 質問が*幅*（複数エンティティのカバー）を必要とし、bridge 質問が*深さ*（特定の推論チェーンの追跡）を必要とするという仮説を検証するものである。本質問タイプ検出器がこの 2 パターンを異なる初期化戦略にルーティングする。

### 6.4 制限事項

1. **コーパス特異性。** 本コーパス（100 学術論文）は HotpotQA の Wikipedia ベース知識源とは異なり、分布シフトの影響がありうる。
2. **評価の厳密性。** 本 9 段階評価は完全一致より寛容だが LLM-as-judge より厳密である。複雑な言い換えによる正解の拒否が残存する。
3. **モデル依存性。** 推論深度制御の改善は GPT-5/o 系モデル固有であり、他のモデルファミリーへの転移は保証されない。
4. **非活性ファクト状態。** ファクトの 99.2% が cascading activation バグにより `inactive` 状態のままである。これの修正と Stage III 矛盾解決の完全有効化は 1–3pt の未開拓改善余地を示す。

---

## 7. 結論

本稿では MemGraphRAG Enhanced を報告し、HotpotQA で String Accuracy 83.6% を達成した — 原論文比 +12.0pt の改善である。主要な貢献は以下の通り:

1. **4 層異種グラフ**と選択的ハブ抑制により、パッセージランキングの品質を改善した。
2. **質問タイプ別検索**により、comparison 質問にエンティティ拡張を、bridge 質問に集中検索を適用した。
3. **推論深度制御**により現代の推論モデルの深い推論能力を活用し、単一改良として最大の精度向上（+6.8pt）を達成した。
4. **ドメイン語彙資源の統合**により、専門用語辞書とシソーラスベースのクエリ拡張を実現した。
5. **厳密な評価方法論**として、9 段階正規化一致関数とフリップ分析によるシグナル・ノイズ分離を導入した。

これらの結果は、適切に構成された推論モデルが、検索パイプラインの変更なしに RAG システムの精度を大幅に改善できることを実証する。検索品質と推論深度の相互作用はさらなる研究に値する: 我々の知見は、**「十分な検索 + 深い推論」パラダイムが「完璧な検索」の追求より費用対効果が高い**可能性を示唆する。
